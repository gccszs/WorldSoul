# Agent Note: WorldSoul Minecraft 网关与玩家 Agent

Status: implemented

[English](2026-09-05-worldsoul-minecraft-gateway.md) | 中文

## 问题

WorldSoul 需要一个可在本地独立部署且不依赖 Minecraft 协议版本的 Agent 服务。聊天与语音请求必须共享玩家上下文，而模型提出的命令仍须经过游戏的命令解析器和权限校验。多人存档还需要玩家间隔离、下线时清理生命周期资源，以及可执行的 token 预算，并在游戏和服务仪表盘中同时显示告警。

## 决策

`worldsoul` profile 将回环 Web 服务器与 `@deepseek-ai/dsh-worldsoul-gateway` 组合。其 HTTP 和 JSON 协议通过存档与玩家标识工作，不导入 Minecraft 类，因此同一套 harness 部署可服务受支持的模组版本。每个存档拥有一个持久的全局 Agent 标识，每个在线玩家拥有一个持久的子 Agent 标识和相互隔离的会话；玩家下线会 dispose（资源释放）实时子运行时，重新上线则恢复其会话。

Agent 创建和恢复会读取共享的 `agentDefaultModel` 选择，并将其作为显式 Agent 选项传入。这使长期运行的 Minecraft 入口与 profile 模型设置保持一致，并防止请求进入没有模型的轮次。网关会把失败的模型轮次转换为非成功 HTTP 响应，并在不暴露供应商详情的前提下识别认证失败。

文字和内存中的 multipart 音频进入同一条玩家轮次路径。音频通过配置的 OpenAI 兼容端点转写，响应同时返回转写文本和 Agent 的纯文本答复。向导模式提供简洁的生存与进度攻略，神明模式提供以命令为中心的人设。提示词禁止 Markdown 与无用铺垫。

模型不能执行 Minecraft 命令。其作用域内的 `minecraft_command` 工具只产生提案，模组随后应用允许列表和 Minecraft Brigadier 解析器，只有完整解析的命令才以配置的权限级别运行。拒绝信息作为私有校验反馈返回同一玩家 Agent，进行有次数上限的重新生成；面向游戏的答复不会包含拒绝详情。

网关分别记录每个全局 Agent 和玩家 Agent 的 token 用量。运维人员可在控制台式仪表盘中查看服务指标、切换存档、检查 Agent 表格与配额进度，并设置硬上限。用量越过配置的告警比例时，模组与仪表盘都会收到告警；达到上限时，该 Agent 被标记为停用，并拒绝后续轮次，直到运维人员提高其上限。仪表盘展示存档和玩家状态，不依赖 Minecraft 渲染 API。

仪表盘通过单调递增的序列游标，将每个玩家的持久化会话投影为实时对话室。投影包含玩家直接消息和 Agent 纯文本回复，但会过滤插件来源的校验反馈与工具流量，使私有恢复详情保持在内部。

同一个仅限回环访问的仪表盘提供面向当前 DeepSeek 路由的 Agent 配置入口。它通过共享设置服务持久化默认模型和推理等级，并通过凭据服务轮换 `DEEPSEEK_API_KEY`。读取只暴露是否存在、来源与可写性；密钥本身绝不会序列化到 HTTP 响应。凭据更新对请求即时生效，模型更新在 Agent 下次创建或重新连接时生效。

玩家模式与游戏状态改为提示词组装时输入。模式端点和仪表盘可在不重建会话的情况下切换向导、神明或沙雕行为；Fabric 命令 `/worldsoul mode <mode>` 使用同一路由。Mod 在每次文字或语音轮次前提供版本无关快照，包括维度、坐标、朝向、生命、饥饿值、游戏模式和着地状态。动态人设读取该快照，不向可见对话添加私有状态消息。

快照还包含当前快捷栏槽位、主背包 36 个槽位中的非空物品，以及头部、胸部、腿部、脚部、主手和副手装备槽位中的非空物品。每组物品只保留注册表 ID、数量和可选耐久。玩家编写的显示名称与物品文本会被刻意排除，避免背包元数据成为提示词指令。

语音提供方设置有独立的持久化仪表盘入口。网关为每次上传读取接口、模型、超时与凭据名称，支持轮换凭据但不返回其值，并在调用提供方前校验 RIFF/WAVE 结构。随附 profile 默认使用基于 FireRedASR-AED-L 官方源码与权重的本机 OpenAI 兼容适配服务。项目内隔离的 Python 3.10 环境承载 CUDA 依赖，启动器会先启动适配服务，适配服务则在串行 GPU 推理前校验有大小限制的 16 kHz 单声道 PCM WAV 输入。仍可通过同一设置切换外部提供方。分阶段转写路由在不启动 Agent 轮次的情况下完成；Mod 会先回显转写结果和思考提示，再通过普通聊天路由提交转写文本。原组合式语音路由作为对旧客户端的增量兼容继续保留。

覆盖范围包括提示词、请求、语音提供方、生命周期、隔离、校验后重新生成和配额单元测试，以及构建后 profile 的冒烟测试。Fabric 模块测试命令策略、WAV 编码、聊天路由和受支持版本元数据；Minecraft 1.20.1 是主要构建版本，1.20.4 复用版本无关的客户端代码。

## 备选方案

- **直接在 harness 中执行命令。** 否决：harness 不掌握服务器实时注册表、权限源或特定版本的解析器，否则会成为 Minecraft 之外的权限主体。
- **一个存档的所有玩家共用一个 Agent 会话。** 否决：对话、私有校验失败和 token 计量会在玩家之间泄漏。
- **在模组中嵌入语音识别。** 否决：捆绑模型会增加客户端体积，并把提供方配置耦合到 Minecraft；模组只录制有大小限制的 WAV 音频，转写由 harness 负责。
- **在普通聊天中返回命令校验错误。** 否决：解析与权限详情是供 Agent 恢复的输入，不是面向玩家的对话。

## 后果

- 新 Minecraft 版本实现同一 HTTP 协议，并在该版本的服务器模块中保留命令校验。
- 首次语音设置会下载固定版本的 FireRedASR 源码、隔离的 CUDA 运行环境与模型权重；语音服务缺失时文字聊天和仪表盘仍可使用。
- 下线会释放实时 Agent 资源，但保留持久的玩家上下文。通过网关删除存档会释放其全局和玩家运行时，并移除对应的内存用量记录。
- 当前仪表盘仅监听回环地址。远程绑定需要部署专用的已认证传输，而不是削弱随附 profile 的限制。
